# Mobile service and developer console scope

Tracking: [personal issue #12](https://github.com/AbigailDeng/NyxID/issues/12). Baseline: `dc46415065fac9e80200d0711b729db7f8c7d2c8`. The native app owns service connections and monitoring. It does not claim to be a mobile copy of the developer or admin console.

There is no generic developer-console directory in Plugins or Services. A connection exposes one contextual **Advanced settings · Web** action (or **View connection details · Web** for platform-managed connections). An eligible SSH connection also exposes its separate **SSH terminal · Web** action. These actions preserve the connection identity, re-check authority, and request a refresh when the user returns.

## Lifecycle and safety

All monitoring queries are account/connection scoped and discarded when unobserved. The display clock expires badges locally without fetching or executing probes. Manual results are in-memory only and expire after at most 60 seconds.

Monitoring writes lock parent Back/tab/connection actions. Unsaved monitoring configuration requires an explicit discard decision before switching tabs. Backgrounding synchronously invalidates captured request authority; returning to foreground cannot revive a preflight from the previous activation. No automatic retries run a probe or write.

Web URLs come from fixed local routes plus encoded resource IDs under the configured HTTPS frontend origin. No mobile token or credential is handed to the browser. Before opening an Advanced or SSH action the app re-checks account/connection authority. A normal browser handoff may background the app: return refresh is queued for the same mounted foreground account without reusing the old preflight generation. The UI accurately says a refresh was requested and requires reviewing server state to confirm changes; closing the browser never proves success.

## Verification and remaining acceptance

Focused tests cover status expiry, encoded unsafe paths, byte/status bounds, missing feature/backend setup, identity/service mismatches, permission revocation, revision drift, uncertain failures, duplicate actions, parent locks, synchronous AppState transitions, the single Advanced action, SSH action eligibility, browser return refresh and account changes.

Pending device/backend acceptance (not claimed complete):

- Flag off/on and a configured chrono-probe deployment; fresh/stale/missing observations on iPhone.
- Explicit Check now/Test draft with real approval/billing behavior; save/clear and a concurrent Web editor conflict.
- App backgrounding during preflight/dispatched operations; return/reload and draft discard UX.
- Native OAuth repair, personal catalog creation and contextual Web handoff with separate browser login.
- Ordinary org member/viewer versus org admin, platform connection, catalog/tool manager and Operator entries.
- Real SSH connection/principal and terminal authorization: [existing integration/device issue #1868](https://github.com/ChronoAIProject/NyxID/issues/1868).

No live configuration, secrets, keys, paid resources or real provider probes were changed for local verification. Full frontend/mobile suite, typecheck and build are delegated to GitHub CI by the personal delivery policy.
