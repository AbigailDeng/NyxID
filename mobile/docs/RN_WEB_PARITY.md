# React Native Web migration — first core increment

This increment starts the mobile migration against the existing NyxID Web and backend contracts. It changes frontend code only; it does **not** deliver full Web parity. Machines are excluded from the migration. The visual reference remains the user-supplied `finalized.html` and the approved [RN Figma design](https://www.figma.com/design/1cxfGMnsqcwgxwxUWyTFrI?node-id=1-557).

## Contract boundaries

The [chat ownership and navigation follow-up](RN_CHAT_NAVIGATION_QA.md) aligns one-to-one Agent selection with Web: saved thread owner first, explicit Agent second, NyxBot by default. History is Agent-scoped, New chat retains the current Agent, selecting an Agent opens its latest thread, and the drawer Chats entry returns to NyxBot. Workspace header returns preserve local detail/form history before route history. These paths were operated in the actual iOS app; multi-agent Groups remain follow-on work.

Backend contracts remain in [NyxAgent handlers](../../backend/src/handlers/assistant_nyxagent.rs), [Agent management handlers](../../backend/src/handlers/assistant_team.rs), [key handlers](../../backend/src/handlers/keys.rs), [catalog handlers](../../backend/src/handlers/catalog.rs), [provider authorization handlers](../../backend/src/handlers/user_tokens.rs), and [auth/MFA handlers](../../backend/src/handlers/auth.rs). No changes to these files are required or included.

- User management uses the user's first-party login session. A restricted Agent Key is not a substitute for full account management authorization. Existing SecureStore, single-flight refresh, push registration and QR validation are reused.
- The server owns state, permissions and supported models. Connection editing respects `can_edit_configuration`, ownership and platform-managed restrictions. Organization service grants retain exact IDs. Agent profile PATCH sends only changed fields; grants replace the selected service access. A fresh read detects conflicts before saving, but these endpoints do not expose a compare-and-swap revision contract, so the client cannot guarantee an atomic edit against concurrent writers.
- Typed credentials and MFA secrets are transient and cleared or masked when leaving the relevant screen/backgrounding. They are not persisted in navigation parameters or query caches. Missing optional catalog/key metadata follows the backend's omitted-field serialization.
- Disconnecting the mobile SSE subscription does not resend the POST. Existing NyxAgent durable execution may continue; recovery reads history before allowing further work. Uncertain sends are not automatically replayed. This is not a guarantee that mobile SSE/audio stays alive in the background.
- Shared OAuth grant removal is not silently cascaded. Error `11500` offers an explicit token-scope single-service removal path, subject to server support. Full sibling-grant cascade review is a follow-on UI.
- **Password change is unavailable without backend work.** [Web Settings](../../frontend/src/pages/settings.tsx) explicitly says `/auth/password/change` is not implemented; its existing form is ahead of backend integration. There is no working password-change path to port in this increment. Earlier feasibility wording that included password change was too broad.
- Real verification/reset email delivery and verification-email resend are incomplete. Recovery codes can be shown when first generated, but recovery-code login/consumption/re-reading/regeneration are not implemented server contracts. These are not included as working RN flows.
- OAuth/push/Universal Links/payment/voice still depend on their documented deployment and native configuration. Closing a browser alone is not proof of authorization or payment completion. Native voice admission compatibility is not established.

## Follow-on frontend work

The following existing Web capabilities are **not yet migrated** by this first increment:

- Chat attachment upload/download/preview; steering submission, feedback, and switching an existing thread's model. Metadata and historical steering may be displayed, but those editing/input paths are not implemented.
- Operation-level grants, Groups, Automations, Triggers and full Channel management. Native exact-version Skills and Learning review/publication are now implemented; their live-validation boundaries are in [Plugins QA](RN_PLUGINS_QA.md).
- Organization creation/membership/invites and organization resource creation, Billing and hosted checkout, full Studio resources including service pools/Agent Keys, Developer OAuth apps and role-gated Admin modules.
- Credential Nodes and SSH management/native terminal, specialized device-code/BYO OAuth/SSH connection setup, OAuth scope editing and full shared-grant cascade review. These currently require the corresponding Web setup.

Artifacts/Assistant Activity/folder placeholders are not treated as new durable backend resources. Machines remain excluded. The password-change correction above takes precedence over the earlier design feasibility assessment.

## Verification status

The [Plugins follow-up](RN_PLUGINS_QA.md) adds a separate production-backed iOS batch: real catalog/connection/history reads, version preview, temporary exact-version skill attachment, pinned-package read, skill history and detach with restoration to the original empty selection. Draft save/publication, feature-gated pin disabling, advanced editing and genuine provider authorization were not completed in that batch. It does not extend the earlier test scopes to those paths.

Focused contract/state/transport tests and changed-file static checks are the local validation scope; full frontend verification is delegated to GitHub CI. **The iOS verification batches for this first core increment are complete**, using the actual RN app in the iOS 26.3.1 Simulator with Expo Go 55.0.34. The [fixture native record](qa/2026-10-13-native-ios.json) contains 78 observations: 66 pass, 8 retained failures from before the repairs, and 4 partial, with 55 reviewed screenshots. The [real-backend native record](qa/2026-10-14-native-backend.json) separately contains 11 passing native observations against the unchanged Rust backend on port 3301: login, profile save/restore, service creation, disable/enable, credential replacement, removal cancellation and confirmed removal, another session's revocation, and logout. Ten have accompanying authenticated HTTP/Mongo readback; the final logout has native UI observation only. The 44 backend API assertions and 16 response-parser cases are separate evidence. The [runtime QA record](RN_RUNTIME_QA.md) preserves these scopes and their limits. The four partial fixture cases remain partial: permanent Agent deletion was cancelled without submission; an earlier background transition may have occurred near completion; tested emoji had missing glyphs with no established cause; and the delayed prior-account response was not continuously observed through arrival. Android, physical devices, release builds, camera/QR trust, push, standalone link handling, genuine provider authorization, live NyxAgent execution and voice remain unverified. Completed iOS batches do not establish full Web parity or acceptance on every platform; tests, API checks and design previews do not establish those unverified behaviors.
